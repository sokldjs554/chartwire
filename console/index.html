ack 는 PostgreSQL 에 커밋된 뒤에만 올라갑니다

그래서 진료실 Wi-Fi 가 끊겨도 무엇이 저장됐는지 서버와 클라이언트가 다투지 않습니다.

chartwire 는 음성차팅 제품(녹음 → 전사 → SOAP 초안) 밑에 깔리는 계층입니다. 무손실 WebSocket 스트리밍, 테넌트 격리, 문장마다 근거가 붙은 초안, 그리고 파기 영수증. STT·LLM 모델을 만들지 않고, 그 모델들이 기대는 바닥을 만들고 그 바닥을 숫자로 잽니다.

포트폴리오 데모입니다 — 합성 데이터, 실제 고객·실제 환자 없음. 공개 데모는 무료 인스턴스라 첫 접속에 1~2분 걸립니다.

환각 초안 — 근거 없는 문장이 차트에 남는다

초안의 모든 문장이 전사 원문을 인용하도록 강제하고, 서버가 8규칙으로 검증합니다. 근거를 못 대면 unsupported 로 표시되고 검토 전까지 서명되지 않습니다.

동의 철회와 10년 보존이 충돌한다

세션 DEK 를 파기해 녹음·전사는 열리지 않게 만들고, 이미 서명된 노트는 진료기록으로 별도 키에 봉인해 남깁니다. 두 요구가 한 테이블에서 싸우지 않도록 키를 나눴습니다(ADR-0004).

수백만 세그먼트에서 한 문장을 찾는다

RLS 아래 ILIKE 검색은 앱 역할에서 41.2 ms 였고, SECURITY DEFINER 검색 함수로 5.8 ms 가 됐습니다(소유자 역할 6.0 ms). 아웃박스 클레임은 207.1 ms → 0.4 ms, 타임라인은 27.4 ms → 2.5 ms.

무중단 배포와 관측 — 배포 중에 녹음이 끊긴다

drain 으로 진행 중인 세션을 밀어내고, 아웃박스는 리스·백오프·DLQ 로 재시도합니다. 시나리오 H 는 이벤트 100000건 · 워커 2 · 테넌트 30 에서 413 events/s · DLQ 0, 워커를 SIGKILL 한 뒤 1345건을 회수했습니다.

한 세션이 지나가는 길

  1. 녹음

    12 B 헤더 + PCM 200 ms 청크를 seq 순으로 보냅니다. ack{ack_seq, credit} 은 원장 행이 PostgreSQL 에 커밋된 뒤에만 옵니다 — 인메모리 ack 는 없습니다.

  2. 라이브 전사 · 위험 경보

    회색 partial 이 final 로 확정되고, 위험 발화에서 배너 + SLA 카운트다운 + ACK 가 뜹니다. 「죽고 싶다는 생각까지는 없어요」는 경보가 아닙니다 — 부정 범위 규칙입니다.

  3. SOAP 초안 · 서명

    문장마다 전사 원문을 그대로 인용하고, 결정론적 검증기 8규칙이 그것을 확인합니다. 출력 스키마에 Assessment·진단 필드가 아예 없습니다 — 평가는 임상의만 씁니다.

  4. 철회 → 파기 영수증 → 복호화 시도

    동의를 거두면 세션 DEK 를 crypto-shred 하고 하드 삭제한 뒤, 삭제 건수와 재계산 해시가 붙은 영수증을 냅니다. 그리고 그 암호문을 다시 열어 failed:dek_destroyed 를 보여 줍니다.

무릎을 숨기지 않습니다

ack p95 는 N=50 에서 223 ms, N=100 에서 449 ms 로 완만하게 늘어납니다. 그러다 N=200 에서 9036 ms 로 무너집니다 — 20배입니다. 무릎의 정체는 처리량 미달이 아니라 이 지연 붕괴이고, 처리량도 같이 꺾여 의도한 1,000 chunk/s 대신 790 chunk/s 에 그칩니다. 병목은 저장소가 아니라 파이썬 프로세스 하나가 코어 하나를 넘지 못하는 것입니다 — api 이벤트 루프와 stt-worker 가 각자 CPU 천장에 붙고 PostgreSQL · Redis 는 한가합니다.

손실 0 · 중복 0 은 시나리오 A–D 에서 확인한 값이지, 어떤 부하에서도 새 세션을 받아낸다는 뜻이 아닙니다. 「떨어뜨리지 않는다」를 시스템 전체에 대한 주장으로 읽으면 안 됩니다. 수평 확장은 미실행입니다.

이 데모가 하지 않은 것

평가하지 않은 것을 「좋다」고 적지 않기 위해 따로 적습니다.

1

STT 품질 · 노트 품질은 평가하지 않았습니다

합성 대본과 STT 시뮬레이터라 실제 진료 음성의 값이 아닙니다.

2

부하 수치는 클라이언트 혼입입니다

같은 박스, 클라이언트 시계로 쟀습니다. 분리 인프라의 값이 아닙니다.

3

위험 탐지는 안전망이지 분류기가 아닙니다

held-out 300문장에서 정밀도 0.76 · 재현율 0.57 — 목표 0.6 에 미달했고, 기준을 낮추는 대신 그대로 싣습니다. 경보가 없다고 위험이 없다는 뜻이 아닙니다.

4

일부 수치는 구성상 높습니다

문법 안에서 만든 10705문장의 정밀도 1.00 · 재현율 1.00 은 자기 테스트 세트 기준이라 회귀 점검용입니다. held-out 세트가 있는 것은 위험 탐지뿐입니다.

5

LLM tier 는 미실행입니다

오프라인 빌드 · API 키 없음. 어댑터와 픽스처 재생 테스트만 있습니다.

6

AWS 인프라는 synth 만, 미배포입니다

cdk-nag 통과 · 템플릿 커밋까지입니다. 공개 데모는 Render 무료 인스턴스에서 돕니다.

5분 투어 — 콘솔 위쪽의 단계 표시를 따라가면 됩니다

  1. 녹음 (Recorder)Start 를 누르면 브라우저 녹음기가 12 B 헤더가 붙은 200 ms 청크를 WebSocket 으로 보냅니다. ack_seq 는 청크가 PostgreSQL 에 커밋된 뒤에만 올라갑니다. 중간에 「네트워크 끊기 5초」를 눌러 보세요 — 재접속 뒤 재전송이 로그에 찍힙니다.
  2. 라이브 전사 · 위험 경보 (Live chart)회색 partial 이 final 로 확정되고, 위험 발화에서 배너와 SLA 카운트다운이 뜹니다. ACK 를 누르면 닫힙니다.
  3. SOAP 초안 · 서명 (SOAP draft)문장을 누르면 근거 발화가 하이라이트됩니다. A(평가)는 「AI가 작성하지 않는 영역」이라 직접 적어야 서명이 됩니다.
  4. 동의 철회 → 파기 영수증 (Consent & purge)철회하면 아웃박스를 거쳐 파기 파이프라인이 돌고, 단계별 삭제 건수와 해시가 붙은 파기 영수증이 남습니다. 영수증 조회는 admin · auditor 권한이라 계정을 바꿔 로그인합니다.
  5. 복호화 시도영수증의 표본 암호문을 다시 풀어 봅니다. 세션 DEK 가 파기되어 failed:dek_destroyed 가 나와야 정상입니다.

상담을 남기면 접수함에 저장됩니다 — 데모라 실제 연락은 가지 않습니다. 기다리지 않고 바로 콘솔에 들어갈 수도 있습니다.

자주 묻는 것

실제 환자 데이터가 들어 있나요?

없습니다. 대본 20개는 문법으로 만든 합성 한국어이고, 환자는 「가상환자-NNNN」입니다.

임상에 쓸 수 있나요?

쓸 수 없습니다. 연구 · 포트폴리오 구현이고 STT 품질과 노트 품질은 평가하지 않았습니다.

상담을 남기면 연락이 오나요?

오지 않습니다. 입력값은 서버에 저장되지만 영업 조직이 없습니다. 접수일로부터 90일 뒤 파기하며, 데모 인스턴스가 기동할 때마다 파기 명령이 돕니다.

데모가 느린데요?

무료 인스턴스 한 컨테이너에 PostgreSQL · Redis · 워커가 함께 들어 있습니다. 여기서 잰 지연은 실측 표와 비교할 수 없습니다 — 빠르게 보려면 docker compose 가 낫습니다.

인증(SOC 2 · HIPAA · ISMS-P)이 있나요?

없습니다. 대신 어떤 통제가 테스트로 고정되어 있는지를 위에 적어 두었습니다.
