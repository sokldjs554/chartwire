# 이 저장소가 만들어진 방식

사람이 방향과 수용 기준을 정하고, 코딩 에이전트가 구현과 측정을 실행하는 방식으로 만들었습니다.
숨길 것이 아니라서 커밋에 그대로 적혀 있습니다 — 이 문서는 그 흔적을 읽는 법입니다.

## 커밋에 이미 적혀 있는 것

전체 108개 커밋 중 **41개**가 공동저자 트레일러를 답니다. 루트 커밋(`5907f38`, 2026-09-02)부터
HEAD 까지 12일 내내 같은 세션입니다.

```
$ git log --format='%b' | grep -oE "Co-Authored-By: Claude [A-Za-z0-9. ]+" | sort | uniq -c
     18 Co-Authored-By: Claude Fable 5.1
     23 Co-Authored-By: Claude Opus 5
```

## `chore: stage → run → remove` 가 반복되는 이유

커밋 목록에 이 패턴이 **29번** 나옵니다. 일회성 스크립트나 GitHub Actions 워크플로를 커밋해서
CI 에서 한 번 실행하고 다시 지우는 방식입니다. 예를 들어

- `b8b8fe6` 이 `.github/workflows/chartwire-ui-assemble-main.yml` 77줄을 추가하고
- `497490f` 이 그 워크플로를 지우면서 결과물(`console/index.html` 재작성)을 남깁니다

작업 산출물이 아니라 **작업 도구**의 수명주기라서, 저장소의 최종 상태에는 아무것도 남지 않습니다.
읽을 가치가 있는 커밋은 본문이 길고 측정치가 들어 있는 쪽입니다.

## 사람이 판단한 것

에이전트가 실행했다고 해서 판단까지 자동인 것은 아닙니다. 두 가지 예:

- **`d7b30f6`** — 콘솔의 숫자 출처 마커가 42개에서 0개가 되면서, CI 의
  `readme_numbers.py --check` 가 *검사할 것이 없다는 이유로* 통과하고 있었습니다. 화면의 449 를
  손으로 12 로 고쳐도 exit 0 이었습니다. 마커를 되돌리고, 마커가 0개인 파일은 실패하도록
  `--require-markers` 를 넣었습니다.
- **`294d223`** — 미리보기 모드가 파기 영수증을 통째로 지어내고 `VERIFIED` · `재계산 해시 일치` ·
  `DEK unwrap 실패` 를 화면에 찍고 있었습니다. 규제 증적의 언어를 브라우저가 만들어 내면 안 되므로,
  증적 경로는 미리보기 답을 주지 않고 영수증 자리를 비우도록 바꿨습니다.

둘 다 「테스트가 초록이니 괜찮다」가 아니라 「무엇을 초록으로 만들고 있는가」를 물어서 나온 변경입니다.

## 무엇을 믿어도 되는가

코드가 무엇을 하는지는 사람이 쓴 설명이 아니라 실행되는 것으로 확인하시면 됩니다.

- `ci.yml` 11개 잡 — lint · 단위(3.11/3.12) · 통합 · 마이그레이션 · docker · cdk · eval · load smoke
- `live-gate.yml` — 공개 URL 이 **이 커밋**을 서빙하는지 확인한 뒤 10가지를 검사합니다
- `frozen-artifacts` 잡 — 문서와 화면의 모든 수치가 측정 JSON 과 일치하는지, 그리고 검사할 마커가
  실제로 존재하는지 확인합니다

측정 조건과 한계는 [`docs/limitations.md`](limitations.md) 에 적어 두었습니다.
