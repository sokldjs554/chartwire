## Test isolation — several agents run tests concurrently on this ONE box
- Every WP uses its OWN test database and Redis DB index so suites never collide:
  `CHARTWIRE_TEST_DB=chartwire_test_<wp>` (e.g. `chartwire_test_b`) and `CHARTWIRE_TEST_REDIS_DB=<n>` (A=1, B=2, C=3, D=4, E=5, F=6, G=7, H=8).
  `tests/conftest.py` (owned by WP-A) MUST honor both variables: it creates/migrates `CHARTWIRE_TEST_DB` (owner URL with that db name) and builds Redis URLs with that index; Redis keys are prefixed with nothing else.
- Never `FLUSHALL` outside your own Redis DB index (`FLUSHDB` on your index only). Never drop another WP's test database.
- Never run the load tests / bulk loader while another agent is testing (measurement is a serial phase run by the integrator).
- Only run the tests you own plus `tests/unit` (fast). Do not run the whole suite.

## Coding rules
- Python 3.11 (no 3.12-only syntax). `ruff check` + `ruff format` clean on the files you touch (config in `pyproject.toml`). mypy strict only on the modules listed in `pyproject.toml`.
- Own only the paths assigned to your WP. If you need a change in another WP's file, do NOT edit it: write the request in `docs/dev/handoff/<your-wp>.md` (create it) with the exact diff you need, and code against the contract in the spec.
- No real PHI, no license text anywhere, no "MIT". Korean UI/README strings; code identifiers in English.
- Every number that ends up in docs must come from a JSON report produced by code (spec §11.4). Do not type measured numbers by hand.
- Do not log transcript text/names/tokens (spec §0.9).
- Keep to the LOC budget for your WP (spec §0). Prefer small, well-tested modules over breadth.
- When you finish, write `docs/dev/handoff/<your-wp>.md`: what you built, what is stubbed, how to run your tests, known issues, and any contract deviations.
